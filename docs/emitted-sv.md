# Emitted SystemVerilog and Verilog-2005

This document describes the code `tern build` (and the internal
`tern emit --ir design.json`) writes: file layout, naming, how each IR
construct is expressed, and what changes with `--std verilog2005`. The
emitter is `src/emit/sv.c`; its API is `src/emit/emit.h`. The IR it reads is
defined in `src/ir/ir.h` (JSON form: `docs/ir-schema.md`). Spec references:
§13.3 (rules), §6.4–6.5 (reset and power-on), §8.3 (CDC), §10.1 (memories),
§10.3 (register maps), §11.3 (assertions).

The goals, in order: the emitted code computes **exactly** what the IR means
(and therefore what `tern test` simulates); it is **readable**, the code an
engineer would write (compare the tour, §2); it uses **no tool-specific
constructs** beyond standard attributes.

## Files

`emit_design()` produces, relative to the output directory
(`build/<target>/` for `tern build`):

| File | Contents |
|---|---|
| `<Module>.sv` / `<Module>.v` | one per non-extern module, named after the emitted module name |
| `<top>_types_pkg.sv` | SV-2012 only, when the design has named structs/enums: every typedef, in dependency order |
| `<Module>_<mem>.hex` | `$readmemh` contents of an initialized memory |
| `<Module>_<mem>.mif`, `.coe` | the same contents for Intel / Xilinx flows (`SV_MEMINIT_MIF`, `SV_MEMINIT_COE`) |
| `<top>.xdc`, `<top>.sdc` | clocks, CDC constraints, CDC report (`src/emit/constraints.c`) |
| `<top>.f` | written by `tern build` to disk (not with `--stdout`): the package and module files in compile order, as paths relative to the directory `tern build` ran in (`iverilog -g2012 -c build/default/Top.f`) |
| `<Map>.h`, `<Map>.svd`, `<Map>.md` | per register map (`src/emit/regmap.c`) |

Order: package, modules (children before parents), memory files,
constraints, register maps. With `--stdout` the files are concatenated, each
after a line `// ---- file: <name> ----`. Source files of `extern` modules
are listed in `SvOutput.extern_files` for the build to copy.

Every HDL file starts with `// <file>: generated by tern from <Display>
(<package>). Do not edit.`; the emitter version is deliberately not part of
the output, so regenerated files only change when the design does.

## Names

* Modules keep their (monomorphized) IR names: `Fifo_u8_64`. Signals keep
  their IR names (`tx_valid` for the flattened bundle field `tx.valid`,
  `r_0` for unrolled loops); instances keep theirs.
* **Keywords.** A name that is a SystemVerilog keyword (IEEE 1800-2017, which
  includes all Verilog-2005 keywords; the same list is used for both
  dialects) gets a trailing underscore: `bit` → `bit_`, `logic` → `logic_`.
  Characters outside `[A-Za-z0-9_]` become `_`; a leading digit gets a `_`
  prefix (`9lives` → `_9lives`).
* **Collisions.** Names are claimed in a fixed order, and a name already taken
  gets more underscores (`bit_` declared next to an escaped `bit` becomes
  `bit__`). Per module the order is: the package names (types and enum
  constants, which are visible through `import`), ports in declaration
  order, the remaining signals, parameters, instances, property labels, and
  finally generated names. Module names are unique among modules and the
  package; extern modules and their ports are never renamed (they name
  existing SystemVerilog).
* **Types.** Named structs and enums keep their IR names (`Pixel`,
  `Fifo_u8_4_State`); enum constants are `<Type>_<Variant>`
  (`Fifo_u8_4_State_Idle`) so that two enums with an `Idle` variant cannot
  collide in the package. Struct fields keep their names (keyword-escaped).
* **Generated names.** Temporaries are `tmp_<n>`; a wire for an
  expression connected to an instance input is `<inst>_<port>`; the
  first-cycle flag of a non-`always` property is `<label>_first`. All are
  checked against every other name in the module.
* `SvNames` (`sv_names_new`, `sv_names_signal`, ...) exposes the same
  mapping to other back ends (constraints, testbench and formal script
  generators).

## Module layout

```systemverilog
// Counter.sv: generated by tern from Counter<8> (demo). Do not edit.
module Counter (  // tern: src/counter.tern:10
    input  logic       clk,  // tern: src/counter.tern:11
    input  logic       rst,  // tern: src/counter.tern:12
    input  logic [7:0] din,  // tern: src/counter.tern:15
    output logic [7:0] count  // tern: src/counter.tern:16
);

    // generic parameters (informational: the module is monomorphized)
    localparam int unsigned W = 8;

    // registers
    logic [7:0] q;  // tern: src/counter.tern:17

    // continuous assignments
    assign count = q;  // tern: src/counter.tern:18

    always_ff @(posedge clk) begin  // tern: src/counter.tern:19
        if (rst) begin
            q <= 8'd0;
        end else if (load) begin  // tern: src/counter.tern:20
            q <= din;
        end else if (en) begin  // tern: src/counter.tern:21
            q <= q + 8'd1;
        end
    end

endmodule
```

* ANSI port list in declaration order, columns aligned. Modules that use
  named types import the package in the header:
  `module M import Top_types_pkg::*; (...)`.
* `IrModule.params` become `localparam`s (they are informational; the module
  is already specialized). Extern module instances get `#(.P(v))`.
* Declarations come before use, grouped: wires (`let`), combinational
  variables (`var`), registers, memories, temporaries. Then: memory
  contents, continuous assignments, instances, `always_comb` blocks,
  `always_ff` blocks, properties.
* Attributes pass through as `(* name = "value" *)` on the declaration:
  `#[ram(block)]` → `(* ram_style = "block" *)`, `#[rom(x)]` → `rom_style`,
  `#[keep]`/`#[dont_touch]`/`#[mark_debug]` → `= "true"`, numbers stay
  numbers (`(* max_fanout = 8 *)`), `#[async_reg]` → `(* ASYNC_REG = "TRUE" *)`.
  Tern-only attributes (`test_port`, `clock`, `top`, `cdc`, `doc`, `sv_name`,
  `encoding`, `allow`, `unsafe_cross`) are not passed through.
  A signal with `unsafe_cross` gets a `// CDC: unchecked` comment on its
  declaration and on its assignment.

### Line markers

Every construct with a source location carries a trailing comment
`// tern: <path>:<line>` (the path as the compiler was given it, normally
relative to the project root). Inside a process a marker that would repeat
the line of the previous one is left out; `tern remap` maps every line to
the nearest marker at or above it, so nothing is lost. `--no-line-markers`
(`SvOptions.line_markers = 0`) removes them.

## Types and values

| IR | SystemVerilog | Verilog-2005 |
|---|---|---|
| `bool`, `clock`, `reset`, 1-bit | `logic` | `wire` / `reg` |
| `uint<N>`, `bit<N>` | `logic [N-1:0]` | `[N-1:0]` |
| `sint<N>` | `logic signed [N-1:0]` | `signed [N-1:0]` |
| named struct | `typedef struct packed` in the package; fields `x.f` | flat vector; fields are part-selects |
| named enum | `typedef enum logic [T-1:0] {E_A = ..., ...} E;` | `localparam [T-1:0] E_A = ...;` in each module that uses it |
| enum with payloads | `E_Tag` enum + `typedef struct packed { E_Tag tag; logic [P-1:0] payload; } E;` | flat vector + tag localparams |
| `[T; N]` | packed array: `logic [N-1:0][W-1:0]`, `Pixel [N-1:0]` (element `i` = bits `[i*W +: W]`, as in the IR) | flat vector |
| anonymous struct/enum | plain vector | plain vector |
| memory | `logic [W-1:0] m [0:D-1]` | `reg [W-1:0] m [0:D-1]` |

Constants are sized: `1'b0`, `3'd5` (decimal up to 9), `8'h1f`,
`130'h3_...` (any width). Values of enum type are written by name
(`state <= Phase_Run`, `state == Phase_Idle`, case labels), and a reset
value of a payload enum as `{Cmd_Idle, 48'd0}`. SystemVerilog enums are
strongly typed, so a non-enum value assigned to an enum target is cast:
`Op'(op)`, `Phase'(go ? Phase_Run : state)`.

## Expressions: exactness

IR operands already have their result width, and the emitter keeps one
invariant: the self-determined width of every emitted subexpression equals
its IR width. Widths change only through constructs that are themselves
self-determined:

* zero extension: `{8'd0, x}`;
* sign extension: `16'(s)` for a signed signal, `16'($signed(a + b))` for an
  expression (Verilog-2005: `{{8{x[7]}}, x}`, through a temporary for an
  expression);
* truncation: `x[3:0]` for a signal, `4'(a * b)` for an expression
  (Verilog-2005: a temporary);
* selects of expressions: a temporary `tmp_0 = a + b; ... tmp_0[8]`, or a
  concatenation of the parts that hold the bits (`{a[3:0], b[7:4]}` for a
  select of `a ++ b`, `{4'd0, a[7:4]}` for a select of a zero-extension).

Signedness matters only for `/`, `%`, `>>>` and `<`, `<=`, `>`, `>=`
(everything else is modulo 2^N at equal widths). Those get explicit
operands — `$signed(a) < $signed(b)`, `$signed(a) >>> n`, and `$unsigned(x)`
for a signed-declared operand of an unsigned comparison — and a signed
operation in a context-determined position (an operand of `+`, `?:`, a
comparison, ...) is wrapped in `$unsigned(...)`, because the surrounding
expression would otherwise turn it unsigned (IEEE 1800-2017 §11.8.2):
`assign y = $unsigned($signed(sa) >>> 2'd1) + a;`.

Other rules:

* Division by zero follows the IR (`x / 0 == 0`, `x % 0 == x`):
  `b != 8'd0 ? a / b : 8'd0`, `b != 8'd0 ? a % b : a`. A non-zero constant
  divisor needs no guard. Signed `MIN / -1` wraps, as in the simulator.
* Shifts by an amount of any width; a constant amount is plain decimal
  (`x >> 1`); shifting by the width or more gives 0 (or the sign).
* A dynamic index that can exceed the array (`[u8; 3]` with a 2-bit index)
  reads 0 and skips writes, as in the simulator:
  `idx < 2'd3 ? small_[idx] : 8'd0`, `if (idx < 2'd3) small_[idx] = b;`.
  The same guard is used for memory reads when the depth is not a power of
  two (`raddr < 4'hc ? ram[raddr] : 16'd0`); out-of-range memory writes are
  ignored by SystemVerilog already.
* Operator precedence: parentheses are added where SystemVerilog precedence
  would differ from the IR and where readers commonly stumble (mixed
  bitwise operators, shifts inside arithmetic, `&&` inside `||`).
* Repeated operands become replications (`{4{a[0]}}`); `$stable`, `$rose`,
  `$fell` are recognized in properties (`x == $past(x)` → `$stable(x)`).

### Temporaries

Temporaries (`tmp_<n>`) are declared in their own group and assigned with a
continuous `assign` right before the construct that uses them; equal
expressions share one. Inside a comb process, an expression that reads a
variable the process itself writes cannot be hoisted (it would see the
final value, not the one at that point). SystemVerilog then uses a size cast
(`4'((v + 8'd1) >> 4)`); Verilog-2005 assigns a process-local temporary right
before the statement and gives it a default at the top of the process so
that no latch is inferred:

```verilog
always @* begin
    tmp_10 = 8'd0;
    v = a + b;
    tmp_10 = v + 8'd1;
    loc1 = tmp_10[7:4];
end
```

## Processes

* Continuous assignments: `assign`.
* Comb processes: `always_comb begin ... end` with blocking `=`.
* Clocked processes: `always_ff @(posedge clk)`, `@(negedge clk)` for
  `clock<falling>`, with non-blocking `<=`.
* `IRST_CASE` → `unique case`; arms with several values list them
  (`A, B: ...`); one-statement arms stay on one line.
* `if` chains become `else if`; an `if` with an empty then-branch is negated.

### Reset (spec §6.4)

The reset branch is generated from the process's `regs` and each register's
`has_init`/`init`, with the domain's reset style:

| Reset | Emitted |
|---|---|
| `reset` (sync, high) | `always_ff @(posedge clk) if (rst) ... else ...` |
| `reset<low>` | `if (!rst_n)` |
| `reset<async>` | `always_ff @(posedge clk or posedge rst)` |
| `reset<async, low>` | `always_ff @(posedge clk or negedge rst_n)`, `if (!rst_n)` |

Registers without a reset value in a process that also has reset registers
are split into a second `always_ff` without the reset (both blocks use the
same conditions, so non-blocking semantics make the split exact); memory
writes go there too. No register gets a reset-enable.

A domain without a reset: power-on values (`reg x = init`) are emitted as an
`initial` block after the process for FPGA targets (`SvOptions.target_kind =
SV_TARGET_FPGA`, the default), and as a `// WARNING: power-on value ...`
comment plus a compiler warning for ASIC targets. A register that is never
assigned keeps its initial value: `assign r = init;`.

### Memories (spec §10.1)

`logic [W-1:0] m [0:D-1]` with the attributes of the `mem`. Initial
contents: `initial $readmemh("<Module>_<mem>.hex", m);` and the `.hex` file
(plus `.mif`/`.coe` when asked); a ROM (never written) of at most 16 words is
initialized inline in an `initial` block. Writes are `m[a] <= d;`; with a
byte mask one statement per byte: `if (mask[1]) m[a][15:8] <= d[15:8];`.
Synchronous reads are what the IR gives (a reset-less register assigned
`m[a]` in the clocked process); asynchronous reads are `assign`s.

### Instances

```systemverilog
assign u2_a = u1_s ^ y;
Adder_8 u2 (  // tern: src/top.tern:15
    .a (u2_a),
    .b (8'd7),
    .s (u2_s),
    .c (u2_c)
);
```

Named connections in the child's port order. Signals, constants and selects
of signals are connected inline (with a cast for an enum-typed port); any
other expression gets a wire `<inst>_<port>`. Unused outputs are `.q()`.

## Assertions (`--emit-assertions`, spec §11.3)

Stripped by default. With `SvOptions.emit_assertions`:

* `IRST_ASSERT` stays in its process under `` `ifndef SYNTHESIS ``:
  `assert (c) else $error("msg");`, `assume (c) else ...`, `cover (c);`. In a
  clocked process outside a reset branch the condition is guarded with the
  reset (`assert (rst || c)`), because the simulator ignores assertions in
  reset.
* Properties become concurrent assertions after the processes, under
  `` `ifndef SYNTHESIS `` and `` `ifndef TERN_NO_SVA `` (define `TERN_NO_SVA`
  for tools without concurrent assertions, such as Icarus Verilog):
  `label: assert property (@(posedge clk) disable iff (rst) ...);`.
  Mapping: `always p` → `p` (SVA checks every cycle); `never p` → `not p`;
  `|->`, `|=>`, `##n`, `##[a:b]`, `##[a:$]`; `eventually[..n] s` →
  `##[0:n] s` (or `s_eventually [0:n] p` for a property); unbounded
  `eventually` → `s_eventually`; `until`, `and`, `or`, `not`; `past(x, n)` →
  `$past(x, n)`; `stable`/`rose`/`fell` patterns → `$stable`/`$rose`/`$fell`.
  An assert/assume property without `always` holds once, at the first edge
  out of reset (spec §11.4); it is emitted with a flag
  `<label>_first |-> p`.
* Verilog-2005 has no assertions: immediate asserts become
  `if (!c) $display("ERROR: %m: msg");` and properties a comment.

## CDC (spec §8.3)

Registers with `#[async_reg]` (the synchronizer flops of `std::cdc`) carry
`(* ASYNC_REG = "TRUE" *)`. The constraint fragments walk the instance tree
from the top:

* `create_clock` for every top clock port whose domain has `hz`;
* per `std::cdc` instance: `set_property ASYNC_REG TRUE` on the synchronizer
  flops (`.xdc`), `set_false_path -to` the first synchronizer stage of
  level/pulse/handshake synchronizers, `set_max_delay -datapath_only` (Vivado)
  / `set_max_delay` (SDC) with the destination clock period for Gray
  pointers of async FIFOs and for handshake/FIFO data registers, and a false
  path to the asynchronous clear/preset of reset synchronizers;
* a comment block with the CDC report (`IrDesign.crossings`).

Cell names follow the tools: Vivado `inst/sub/r_reg` (`r_reg[*]` for
vectors, `m_reg*` for RAMs), Quartus `inst|sub|r` (`r[*]`).

## Register maps (spec §10.3)

* `<Map>.h`: include guard, `<MAP>_<REG>_OFFSET`, per field `_SHIFT`,
  `_WIDTH`, `_MASK`, `_GET(v)`, `_SET(v, x)` and enum value constants, plus
  `static inline` volatile accessors `<map>_read_<reg>(base)` /
  `<map>_write_<reg>(base, v)` (no bit-field structs). Names are upper/lower
  snake case (`DmaCtrl` → `DMA_CTRL`).
* `<Map>.svd`: CMSIS-SVD 1.3 (`device` / `peripherals` / `peripheral` /
  `registers` / `register` / `fields` / `field`); access `rw` → read-write,
  `ro` → read-only, `wo` → write-only, `w1c` → read-write with
  `modifiedWriteValues` `oneToClear`, `rw1s` → `oneToSet`; enum fields get
  `enumeratedValues`; readable stream registers `readAction` `modify`.
* `<Map>.md`: an overview table and one field table per register.

## Verilog-2005 (`--std verilog2005`)

* `wire` for signals driven by `assign` or an instance, `reg` for signals
  assigned in a process; `input wire`, `output wire` / `output reg`.
* `always @(posedge clk ...)`, `always @*`; plain `case`. When the arms do not
  cover every value and there is no default arm, a `default` is added: empty
  in clocked processes; in comb processes it assigns `'bx` (don't care) to
  the targets that are not assigned before the `case`, so that no latch is
  inferred (the IR rules those values out).
* Structs, arrays and enums are flat vectors; fields are part-selects;
  enum constants are `localparam`s in every module that uses them; no
  package, no `logic`, no casts (temporaries instead).
* Immediate assertions as `$display` checks; properties omitted.

## Testing

`tests/unit/test_emit.c` builds designs with the IR builder for every
construct, compares the emitted files with `tests/fixtures/emit/<name>/`
(SV-2012) and `tests/fixtures/emit/<name>_v2005/` (`UPDATE=1` rewrites
them), checks that emitting the JSON round trip of each design gives the
same files, compiles every file set with Icarus Verilog (`-g2012` / `-g2005`)
when it is installed, and for several designs runs a generated
random-stimulus testbench (`tests/fixtures/emit/<name>/tb/tb.v`) under `vvp`
and compares every cycle, for both dialects, with the Tern simulator on the
same IR. CI additionally lints the fixtures with Verilator and synthesizes
the Verilog-2005 ones with Yosys (`tests/lint_emitted.sh`).

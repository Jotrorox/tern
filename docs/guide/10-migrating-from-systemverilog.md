# 10. Migrating from SystemVerilog

Tern is built to be adopted one module at a time. It reads existing
SystemVerilog as typed black boxes and writes SystemVerilog for every tool
that exists today, so a mixed design builds from the first day (spec §13.4,
§13.5 and appendix B).

## The migration path

1. `tern new`, then `tern import` the existing tree. Every SystemVerilog
   module becomes an `extern module`, and the build works on day one.
2. Rewrite leaf modules in Tern one at a time, each with a `test`. The emitted
   SystemVerilog replaces the original in the same flow.
3. Move interfaces to bundles once the modules on both sides are converted.
4. Delete `extern` declarations as they empty out.

## Importing

```sh
tern import rtl/uart_tx.sv                       # print to stdout
tern import rtl/uart_tx.sv -o src/uart.tern --package uart
tern import rtl/ -o src/legacy --package legacy  # a whole tree, one .tern per file
```

For this SystemVerilog header:

```systemverilog
module uart_tx #(parameter int CLK_HZ = 50_000_000, parameter int BAUD = 115_200) (
    input logic clk, input logic rst,
    input logic tx_valid, input logic [7:0] tx_data,
    output logic tx_ready, output logic txd);
```

`tern import` writes:

```tern
// Generated by `tern import` from rtl/uart_tx.sv; review every TODO.
package legacy

/// `uart_tx` from rtl/uart_tx.sv:1.
extern module uart_tx("rtl/uart_tx.sv") <CLK_HZ: uint = 50_000_000, BAUD: uint = 115_200> {
    in clk: clock // TODO: confirm: clock (from the name)
    in rst: reset // TODO: confirm: reset (active-high from the name; synchronous assumed)
    in tx_valid: bool
    in tx_data: uint<8>
    out tx_ready: bool
    out txd: bool
}
```

`tern import` is a header parser, not a full SystemVerilog front end. It
guesses clocks and resets from port names and marks every guess with a
`// TODO: confirm`. You then add what SystemVerilog cannot express: the right
`clock` and `reset<...>` types, and bundles in place of loose
valid/data/ready triples. [migration.md](../migration.md) lists the complete
mapping (parameters, packed arrays, signedness, `inout`, keywords used as
names) and its limits.

An extern module is used like any other module. Tern checks every connection
against the declared types:

```tern
package mixed

extern module uart_tx("rtl/uart_tx.sv") <CLK_HZ: uint = 50_000_000, BAUD: uint = 115_200> {
    in clk: clock
    in rst: reset
    in tx_valid: bool
    in tx_data: uint<8>
    out tx_ready: bool
    out txd: bool
}

/// New Tern code around the legacy transmitter.
#[top]
module Top {
    in clk: clock
    in rst: reset
    in bytes: Stream<u8>
    out txd: bool

    let tx = uart_tx<CLK_HZ: 100_000_000>(tx_valid: bytes.valid, tx_data: bytes.data)
    bytes.ready = tx.tx_ready
    txd = tx.txd
}
```

`tern build` copies `rtl/uart_tx.sv` next to the emitted files. Tests of a
design with an extern module run on Verilator (`tern test` picks it when it
is installed; [chapter 7](07-testing-and-verification.md#designs-with-extern-modules)),
so the mixed design is tested as a whole while leaves are converted.

When a synthesis or lint tool complains about the emitted code,
`tern remap` translates its log back to Tern source lines
([chapter 9](09-toolchain.md#logs-back-to-source)).

## Cheat sheet

| SystemVerilog | Tern |
|---|---|
| `logic [7:0] x;` | `let x: u8 = ...` / `var x: u8` / `reg x: u8 = 0` |
| `assign y = a & b;` | `y = a & b` (or `let y = a & b`) |
| `always_comb begin ... end` | `comb { ... }` |
| `always_ff @(posedge clk) if (rst) ... else ...` | `on clk { ... }` with reset values on the `reg`s |
| `q <= d;` | `q = d` inside `on` |
| `case (x) ... default: ... endcase` | `match x { ..., _ => ... }`, exhaustive |
| `c ? a : b` | `if c { a } else { b }` |
| `{a, b}` | `a ++ b` |
| `x[3 +: 4]` | `x[6:3]` |
| `$clog2(N)` | `clog2(N)` |
| `'0`, `'1` | `all0`, `all1` |
| `8'hFF` | `0xFFu8`, or `0xFF` in a `u8` context |
| `a + b` (wraps) | `a +% b` (wraps), or `a + b` (one bit wider) |
| `$signed(x)` | `x as sint<N>` or `widen_signed(x)` |
| `parameter int W = 8` | `module M<W: uint = 8>` |
| `localparam` | `const` |
| `generate for (...) ... endgenerate` | `for i in 0..N { ... }` |
| `` `ifdef DEBUG `` | `if cfg::debug { ... }` |
| `` `define ``, `` `include `` | `const` / `const fn`, `use` |
| `interface` + `modport` | `bundle` with `flip` |
| `m u_m (.clk(clk), .a(a), .y(y));` | `let m = M(a)`, then read `m.y` |
| `typedef enum logic [1:0] {...} t;` | `enum T { ... }` |
| `typedef struct packed {...} t;` | `struct T { ... }` |
| `logic [7:0] ram [0:255];` | `mem ram: [u8; 256]` |
| `assert property (@(posedge clk) a \|=> b);` | `property p { always a \|=> b }` |
| `initial begin ... $finish; end` | `test "..." { ... }` |
| `inout` | `tri<T>`, only on a `#[top]` module |

## A worked example

A typical SystemVerilog counter with an enable, a synchronous active-low
reset and a terminal-count flag:

```systemverilog
module counter #(parameter int W = 8, parameter int MAX = 200) (
    input  logic         clk,
    input  logic         rst_n,
    input  logic         en,
    output logic [W-1:0] count,
    output logic         done
);
  always_ff @(posedge clk) begin
    if (!rst_n)       count <= '0;
    else if (en)      count <= (count == MAX) ? '0 : count + 1'b1;
  end
  assign done = (count == MAX);
endmodule
```

In Tern:

```tern,test
package counter

module Counter<W: uint = 8, Max: uint = 200>
where Max < (1 << W)
{
    in clk: clock
    in rst: reset<low>
    in en: bool
    out count: uint<W>
    out done: bool

    reg value: uint<W> = 0
    on clk {
        if en { value = if value == Max { 0 } else { value +% 1 } }
    }
    count = value
    done = value == Max
}

test "wraps after Max" {
    let dut = sim Counter<W: 4, Max: 9>()
    dut.reset()
    dut.en = true
    dut.step(9)
    expect dut.done
    dut.step()
    expect dut.count == 0 and !dut.done
}
```

What changed:

* The reset polarity is in the port type (`reset<low>`), and the reset value
  is on the register. The module never tests `rst_n`.
* `where Max < (1 << W)` turns a silent misconfiguration into a compile error
  at the instantiation.
* `value +% 1` says the add wraps. `value + 1` would be one bit wider and
  rejected when assigned back.
* The test lives in the same file and runs with `tern test`.

## Things that are deliberately missing

* **4-state logic.** Tern is 2-state. Reset-less registers start with
  pseudo-random values in simulation, a different set per seed, so a design
  that relies on an uninitialized value fails a test instead of passing by
  luck.
* **Latches.** They cannot be written in Tern. Import one with
  `extern module` if you really need it.
* **`#delay` timing and event scheduling.** The simulator is cycle-based.
* **Internal tri-states.** `tri<T>` exists only on top-level ports.
* **`force` in tests.** Tests drive inputs only.
* **Implicit nets, implicit truncation, implicit signed/unsigned mixing.**
  All of them are compile errors.

The words `wire`, `logic`, `initial` and `generate` are reserved, so pasted
SystemVerilog produces a "this is not Tern" message instead of a confusing
parse error:

```tern,fail
module Pasted {
    in a: bool
    out y: bool
    wire t = a
    y = t
}
```

```
pasted.tern:4:5: error: `wire` is SystemVerilog, not Tern
  |
4 |     wire t = a
  |     ^^^^
  = help: a wire is `let name = expr`; a combinational variable is `var name: T`
```

# Packages: `tern.toml`, `tern.lock` and the package commands

A Tern package is a git repository with `tern.toml`, `src/` and `tests/` at
its root; versions are semver tags (`v1.2.0`). There is no upload step and no
server holding code: a public *index* (itself a git repository, see
[registry.md](registry.md)) maps short names to git URLs and published tags
(spec §13.6).

Only `tern add`, `tern update`, `tern vendor` and `tern publish` run `git` and
touch the network. `build`, `check`, `test` and the language server read
dependencies from the cache or `vendor/` as recorded in `tern.lock`.

## `tern.toml`

```toml
[package]
name = "my-soc"                 # required: letters, digits, `_`, `-`
version = "0.3.0"               # required: semver
description = "A small SoC"
authors = ["Ada <ada@example.com>"]
license = "MIT"
repository = "https://github.com/acme/my-soc"   # optional; default: git remote `origin`

[dependencies]
axi = "1.2"                                                   # registry (index), requirement
uart-ip = { git = "https://github.com/acme/tern-uart", tag = "v2.0.1" }
spi = { git = "https://github.com/acme/tern-spi" }            # newest vX.Y.Z tag (else HEAD)
dma = { git = "https://github.com/acme/tern-dma", version = "0.4" }  # newest matching tag
dev = { git = "https://github.com/acme/tern-dev", branch = "main" }  # or rev = "<commit>"
vendor-ip = { path = "../vendor-ip" }                         # local directory

[features]
debug_ila = false               # default value of cfg::debug_ila

[target.arty]
device = "xc7a35t"
top = "Top"
backend = "vivado"
std = "sv"                      # or "verilog2005"
clock_hz = 100_000_000          # any other key is kept for back ends

[registry]
index = "https://github.com/tern-lang/registry"   # default; TERN_INDEX overrides
fork = "git@github.com:me/registry.git"          # where `tern publish` pushes the index branch
```

* A dependency's key is its name in this project and its `use` root, with `-`
  replaced by `_` (`use uart_ip::UartRx`). A fork can be used under its own
  URL without renaming.
* `git` dependencies take at most one of `tag`, `rev`, `branch`; a `version`
  requirement selects among the repository's semver tags.
* Feature names must be identifiers (they are read as `cfg::<name>`); their
  value is the default. Command lines can override them (`--features a,-b`).
* The file is a TOML subset: tables, dotted headers, `[[arrays of tables]]`,
  dotted keys, bare/quoted keys, basic/literal and multi-line strings,
  integers (`0x`, `0o`, `0b`, `_`), booleans, multi-line arrays, inline tables.
  Floats and dates are rejected. Every error has a line/column and most have a
  suggested fix; unknown sections and keys are warnings (with "did you mean").

### Version requirements

| Requirement | Matches |
|---|---|
| `"1.2"`, `"^1.2"`, `"^1.2.0"` | `>=1.2.0, <2.0.0` |
| `"0.4"`, `"^0.4.1"` | `>=0.4.0, <0.5.0` / `>=0.4.1, <0.5.0` (for 0.x the minor is breaking) |
| `"^0.0.3"` | `=0.0.3` |
| `"~1.2"`, `"~1.2.3"` | `>=1.2.0, <1.3.0` / `>=1.2.3, <1.3.0` |
| `"=1.2.3"`, `"=1.2"` | exactly 1.2.3 / `>=1.2.0, <1.3.0` |
| `">=1.0, <2"` | comparators separated by commas, all must hold |
| `">1.2"`, `"<=1.4"` | `>=1.3.0` / `<1.5.0` |
| `"*"`, `"1.*"` | anything / `>=1.0.0, <2.0.0` |

Pre-releases (`1.3.0-rc.1`) only match a requirement that names the same
`MAJOR.MINOR.PATCH` with a pre-release (`"=1.3.0-rc.1"`, `"^1.3.0-rc.1"`).
Yanked index versions are never chosen unless already locked.

## `tern.lock`

Generated by `tern add`/`tern update`; commit it. Builds are reproducible from
it.

```toml
# tern.lock: generated by `tern add` / `tern update`; do not edit by hand.
version = 1
vendored = true                 # only after `tern vendor`

[[package]]
name = "axi"
version = "1.2.3"
source = "registry+https://github.com/acme/tern-axi"   # or "git+<url>", "path+<dir>"
tag = "v1.2.3"                  # or rev / branch (the pin of a git dependency)
commit = "4f38a495a19ff63c6b73c8088e19b1c6f67e787c"
dependencies = ["stream-utils"]
```

Path dependencies are recorded relative to the project root and have no commit.

## On-disk layout

| Path | Contents |
|---|---|
| `$TERN_HOME` (default `~/.tern`) | everything below |
| `$TERN_HOME/index/` | shallow clone of the registry index |
| `$TERN_HOME/cache/<name>/<commit>/` | package checkouts (no `.git`; immutable) |
| `<project>/vendor/<name>/` | vendored copies (`tern vendor`), with `.tern-vendor` holding the commit |

Environment: `TERN_HOME`, `TERN_INDEX` (index URL), `TERN_INDEX_FORK` (push URL
for `tern publish`). Builds use `vendor/<name>/` when its `.tern-vendor` commit
matches the lock (always, and exclusively, when `vendored = true`), otherwise
the cache.

## Resolution

The dependency graph is resolved transitively: every package's own
`tern.toml` adds requirements. For each name the newest version that satisfies
*every* requirement on it wins, unless the version in the existing
`tern.lock` still satisfies them (then it is kept, so adding one dependency does
not move the others). All requirements on one name must agree on the source
(registry, a git URL, or a path) and on a git pin. When nothing fits, the error
lists who requires what and which versions exist:

```
error: cannot resolve `stream`: no version satisfies every requirement
  = note: available versions of `stream`: 1.0.0, 1.1.0, 2.0.0
  = help: relax one of the requirements so that a single version satisfies all of them
tern.toml:7:1: note: `my-soc` requires `stream` ">=2.0" from the index
.../axi/tern.toml:6:1: note: `axi` requires `stream` "1.0" from the index
```

Registry versions come from the index; each index version records the tag and
its commit, and a fetched tag that now points elsewhere is an error ("the tag
was moved"). Git dependencies without a pin use `git ls-remote --tags`.

## Commands

All of them print short progress lines on stderr (`-q` silences them for `add`,
`update` and `vendor`), report
errors with a fix, and accept `--help`.

### `tern new <name> [--no-git]`

Creates `<name>/` with `tern.toml` (package, commented dependency examples,
`[features]`, `[target.default]`), `src/<name>.tern` (a blinky module with a
`test`), `tests/<name>_test.tern`, `.gitignore` (`/build/`; `vendor/` is meant
to be committed when used) and `README.md`, then runs `git init` when git is
available and the directory is not already inside a repository (a failure is
only a warning). Authors come from `git config user.name/user.email`.

### `tern add`

```
tern add axi                       # newest release, written as axi = "1.2.3" (caret)
tern add axi@1.2 dma@~0.4          # explicit requirements, several at once
tern add https://github.com/acme/tern-uart              # newest vX.Y.Z tag
tern add https://github.com/acme/tern-uart --tag v2.0.1 # or --rev <commit> / --branch <b>
tern add ../tern-uart              # a local git checkout (file:// URL), newest vX.Y.Z tag
tern add --path ../vendor-ip       # local package
tern add                           # fetch everything tern.lock says (after a clone)
```

The dependency line is replaced or appended in `[dependencies]` (created at the
end of the file if missing); the rest of `tern.toml` is kept byte for byte,
including comments and CRLF line endings. Git and path dependencies are named
after their `[package] name` unless `--name` is given. The edited manifest is
resolved and fetched before anything is written: on any error neither
`tern.toml` nor `tern.lock` changes. If the project is vendored, `vendor/` is
refreshed too.

### `tern update [<pkg>...]`

Refreshes the index and moves the named packages (default: all) to the newest
versions their requirements allow, then rewrites `tern.lock`
(`Updating axi v1.2.0 -> v1.3.1`). Git dependencies pinned by tag stay; branch
pins move to the branch head.

### `tern vendor [--remove]`

Makes sure `tern.lock` is current and fetched, then copies each locked git or
registry package (only `tern.toml`, `src/`, `tests/`, `LICENSE*`, `README*`)
to `vendor/<name>/`, removes vendored packages that are no longer dependencies,
and sets `vendored = true` in `tern.lock`; from then on builds read only
`vendor/` (air-gapped flows). Path dependencies are not copied. `--remove`
deletes the copies and clears the flag.

### `tern publish [--dry-run] [--fork <url>] [--pr]`

1. Checks that the project is a git repository with a clean working tree, that
   `v<version>` is not yet tagged locally or on `origin`, that there are no path
   dependencies, and that the name is free in the index (or registered to the
   same git URL) and the version is new.
2. Creates the annotated tag `v<version>` at `HEAD` and pushes it to `origin`.
3. Writes the index entry (`<first-two-letters>/<name>.toml`, see
   [registry.md](registry.md)) on branch `publish/<name>-<version>` of the local
   index clone and commits it.
4. Pushes that branch to your fork of the index (`--fork`, `TERN_INDEX_FORK` or
   `[registry] fork`), and with `--pr` runs `gh pr create` when `gh` is
   installed (interactively, so gh can also create the fork). Otherwise it
   prints the exact `git push` and `gh pr create` commands.

`--dry-run` performs the checks and prints the tag, the branch and the index
entry without changing anything.

## API for the compiler front end (`src/pkg/pkg.h`)

```c
PkgProject prj;
int r = pkg_project_open(".", &prj);   /* 1 loaded, 0 no tern.toml, -1 errors (reported) */
/* prj.manifest: name, version, targets (pkg_manifest_target), features
   (pkg_manifest_feature(&prj.manifest, "debug_ila", &value) -> cfg::debug_ila;
   pkg_features_apply(&prj.manifest, "a,-b") for --features)
   prj.deps.items[i]: name, ident (`use` root), version, root, src, vendored, direct */
pkg_project_close(&prj);
```

`pkg_project_open` never runs git; a missing or stale lock, or an unfetched
package, is an error that says which command fixes it.

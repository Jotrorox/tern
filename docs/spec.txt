Tern
A Modern Hardware Description Language
Language Specification
Version 0.1 — 3 November 2026
Johannes Müller
tern-lang.com
Tern is a synthesis-first hardware description language: everything that compiles is
hardware, every signal is typed with a width and a clock domain, tests live beside
the design, and the compiler emits clean SystemVerilog so it drops into any existing
flow. This document is the normative specification of the language, its standard
library and its toolchain. The reference implementation is written in portable C (C11,
C99-compatible) with no third-party dependencies.

1 Introduction
1.1 What Tern is
Tern describes synchronous digital hardware. A Tern design is a tree ofmodules; a module is a set
of typed signals — wires, combinational variables and registers — connected by expressions and
grouped into blocks that give those expressions their meaning. There is no event scheduler, no
simulation-only subset, and no construct whose synthesis behaviour differs from its simulation
behaviour.
The language optimizes, in this order, for being hard to misuse, easy to read, and a drop-in
replacement for SystemVerilog in synthesis and simulation flows. The goal is a language an
engineer can learn in an afternoon and a team can run a whole chip project in.
1.2 The name
The Arctic tern makes the longest migration of any animal, pole to pole, every year. Tern is built
around migration: it reads existing SystemVerilog as typed black boxes, emits SystemVerilog for
every tool that exists today, and lets a team move one module at a time. Source files end in.tern,
the command-line tool istern, and the project’s home — documentation, the standard-library
reference and the package index — is tern-lang.com. In prose, “Tern” is the language; “tern lang”
is used where a disambiguator is needed.
1.3 What goes wrong in SystemVerilog
Table 1.1 lists the SystemVerilog behaviours that cause most bugs and most of the learning curve,
and what Tern does instead. Each row corresponds to a rule in this specification.
1.4 Design goals
1. Everything synthesizes.If it compiles, it is hardware.
2. One mental model.Wires, combinational variables and registers connected by expressions.
3. Learnable in an afternoon.Rust/Go-flavoured syntax, 38 keywords, one assignment
operator, nobegin/end.
4. Correct by construction where cheap.No latches, no width surprises, no unconnected
inputs, no implicit clock-domain crossings, no multiple drivers — all compile errors.
5. Generic and compile-time programmable. Type and value generics, const fn,
elaboration-time loops and conditionals.
6. Testing is part of the language.test blocks, assertions, a small temporal property
language and a cycle-based simulator ship with the compiler.
7. Interoperates with the existing world.Reads SystemVerilog modules as typed black
boxes; emits readable SystemVerilog and Verilog-2005.
8. Batteries included. One CLI for build, test, format, lint, docs and packages, and a
standard library of universal components.

1.5 Non-goals
• Replacing UVM or full constrained-random verification environments. Tern tests are for
unit and block-level verification.
• Analog, mixed-signal, or gate-level netlist entry.
• Event-driven simulation with arbitrary#delay timing. The simulator is cycle-based.
• Latch-based or asynchronous (clockless) design. Latches can be imported from SystemVerilog,
never written in Tern.
• 4-state simulation. Tern is 2-state (see Decisions, Chapter 14).
• A hardware-construction DSL embedded in a host language. Tern’s compile-time language
is deliberately small.
1.6 Prior art
Chisel and SpinalHDL (Scala), Amaranth (Python) and Clash (Haskell) get the semantics right but
require learning a host language first. Bluespec is powerful but far from RTL thinking. Veryl is the
closest standalone attempt: Rust-like syntax that transpiles to SystemVerilog. Tern takes Veryl’s
position (standalone language, SystemVerilog output) and adds Chisel’s typed clock domains and
bundles, lossless arithmetic, and built-in testing.

2 Language tour
The same 8N1 UART transmitter is 38 lines in Tern and 62 in SystemVerilog, and the Tern version
cannot contain a latch, a race, a width bug or a missed reset.
package uart
use std::stream::Stream
/// Sends one byte per ‘tx‘ handshake, 8 data bits, no parity, 1 stop bit.
module UartTx<ClkHz: uint, Baud: uint = 115_200> {
in clk: clock
in rst: reset
in tx: Stream<uint<8>> // valid + data in, ready out
out txd: bool
const Div: uint = ClkHz / Baud
static_assert(Div >= 16, "clock too slow for this baud rate")
enum State { Idle, Start, Data, Stop }
reg state: State = .Idle
reg tick: uint<clog2(Div)> = 0
reg bit: uint<3> = 0
reg shift: uint<8> = 0
let baud_tick = tick == Div - 1
tx.ready = state == .Idle
txd = match state {
.Idle | .Stop ⇒ true,
.Start ⇒ false,
.Data ⇒ shift[0],
}
on clk {
tick = if baud_tick or state == .Idle { 0 } else { tick +% 1 }
match state {
.Idle ⇒ if tx.valid { shift = tx.data; state = .Start },
.Start ⇒ if baud_tick { state = .Data },
.Data ⇒ if baud_tick {
shift = shift >> 1
bit = bit +% 1
if bit == 7 { state = .Stop }
},
.Stop ⇒ if baud_tick { state = .Idle },
}
}
}
test "sends 0x55 LSB first" {

What to notice:
• One assignment operator. Insideon clk, state = .Start sets the register’s next value; at
module level,txd = ... is a continuous assignment.
• Reset is never written by hand.reg state = .Idle gives the reset value; thereset port
type says whether it is synchronous or asynchronous and which polarity.
• match must cover everyState, so there is nodefault and no latch to forget.
• tick +% 1 is a wrapping add that keeps the width; a plaintick + 1 is one bit wider and
is rejected when assigned back.
• Stream<uint<8» is a bundle:valid and data flow in,ready flows out, because the port is
in.
• The test is in the same file, uses the same types, and runs withtern test. The harness
drives clk and rst because the module has exactly one clock domain.

3 Lexical structure
3.1 Source text
Source files are UTF-8. Identifiers are ASCII; string literals and comments may contain any
Unicode. A statement ends at the end of its line; a semicolon separates two statements on one
line. Blocks are delimited by braces. There is no preprocessor.

3.3 Keywords
The 38 keywords are reserved everywhere:
package use pub module extern bundle struct enum const fn type regmap domain
where test property sequence in out flip let var reg mem on comb match if
else for while return as sim expect assert assume cover
clock, reset, uint, sint, bit, bool, tri are built-in type names, not keywords.and, or, not,
xor are the logical operators (the symbols&&, ||, ! are accepted as synonyms).static_assert,
always, never, eventually, until are contextual: ordinary identifiers outside their constructs.
Reserved for future use and rejected today with a dedicated message:impl, trait, async, yield,
generate, initial, wire, logic — the last four so that pasted SystemVerilog produces “this is
not Tern” rather than a confusing parse error.

4 Packages and files
A Tern project is a directory tree of.tern files. Each file belongs to one package, packages map
to directories, and there is noinclude.
• A file starts withpackage <name>; files in the same directory must declare the same package.
package uart::rx lives inuart/rx/.
• use pkg::Itemimports one name,use pkg::{A, B} several, use pkg::* everything public.
Items are private unless markedpub.
• The project root holdstern.toml (Section 13.6).tern build compiles every package under
src/; tern test also compilestests/.
• Top-level items: module, extern module, bundle, struct, enum, const, const fn, fn,
type, regmap, test, property, sequence.
• std::prelude is imported into every file. Names from it can be shadowed by an explicit
use.

narrows silently, and clocks and resets are types of their own, so they cannot be used as data by

5.2 Width rules
The lossless principle: an arithmetic result is wide enough to hold every possible value, so no
operator can overflow unless the programmer asks for wrapping.
5.3 Conversions
• Implicit, always allowed:uint<N>→ uint<M> for M≥ N (zero-extend); sint<N>→
sint<M> for M≥ N (sign-extend); untyped literal→ any integer type that can hold it;
bit<N>→ uint<N> and back.
• Explicit only: x as uint<8> (truncate or extend),x as sint<9> (reinterpret or extend),
x as bit<N> (forget signedness),x as bool (x != 0), bits(x) (any value to its raw bits),
T::from_bits(b) (the reverse, e.g. for an enum or struct).
• Mixing uint and sint in one operator is an error until one side is cast. The function
widen_signed(x) in std::math converts uint<N> to sint<N+1> losslessly.

5.4 Structs and enums

enum Op { Nop, Add, Sub, Load } // 2 bits, binary encoded
enum Cmd { // enum with payload: a tagged union

let p = Pixel { r: 255, g: 0, b: grad[7:0] }

let c = Cmd::Write { addr: 0x10, data: payload }
let a = match c { .Write { addr, .. } | .Read { addr } ⇒ addr, .Idle ⇒ 0 }
Enums with payloads are packed astag ++ payload, the payload padded to the largest vari-
ant. They replace the unsafe union plus manual tag pattern. An enum variant is written
.Name when the type is known from context andType::Name otherwise. #[encoding(binary)],
#[encoding(onehot)] and #[encoding(gray)] choose the tag encoding.
5.5 Arrays
[u8; 16] is 16 elements, indexeda[i] with auint<4> index. Out-of-range constant indices are
compile errors; a dynamic index must be exactly wide enough (so every index is in range) or be
an enum. a.len, a.map(f), a.reduce(f) and a.zip(b) exist at elaboration time for building
logic, not as runtime hardware.
5.6 Clock-domain typing
A reg carries its domain in its type:reg x: uint<8> @ clk_b . Reading a register from one
domain in logic clocked by another is an error unless the read goes through astd::cdc primitive.
Combinational logic has the domain of the registers it reads; purely constant logic is domain-free.
This is the check SystemVerilog does not have (details in Chapter 8).

• A module with exactly oneclock port (and at most onereset) has adefault domain; reg
and on clk may omit it. Two clock ports mean everyreg must say@ which.
• Inside on clk, reading areg gives the value before the edge, always; writing it sets the
value after the edge. This is SystemVerilog’s non-blocking assignment, and it is the only
kind. Intermediate combinational values inside the block arelet bindings.
• A reg not assigned on some path keeps its value: an enable is inferred. This is the one place
“not assigned” is not an error, because a register holding its value is a flip-flop, not a latch.
• A reg may be assigned several times in one block; the last assignment in program order
wins, as in SystemVerilog.
6.4 Reset model
• The reset port type carries the style:reset = synchronous, active-high.reset<async>,
reset<low>, reset<async, low> change it. The compiler generates the right sensitivity
list and polarity; no module ever writesif (!rst_n).
• reg x: T = init resets toinit from the domain’s reset.reg x: T has no reset. A reset
value must be a compile-time constant.
• A domain with aclock but noreset is allowed; everyreg in it is reset-less, and= init
becomes a power-on initial value only (emitted asinitial for FPGA, a warning for ASIC
targets).
• Reset is never read as data.rst as bool is an error; a design that needs “are we in reset”
uses areg in_reset: bool = true that it clears.
6.5 Power-on and uninitialized registers
A reset-less reg read before any write on some path is a warning fromtern check (an error
with –strict). In simulation its initial value is pseudo-random per seed (tern test –seed), so
a design that silently relied on zeros fails deterministically rather than passing by luck.

7 Modules, generics and elaboration
A module instance is an expression: inputs are passed by name, outputs are read as fields, and
clocks propagate implicitly, so an instantiation is one line instead of a port map.
7.1 Declaring a module
pub module Fifo<T: type, Depth: uint = 16>
where Depth.is_pow2()
{
in clk: clock
in rst: reset
in push: Stream<T>
out pop: Stream<T>
out count: uint<clog2(Depth) + 1>
...
}
• Generics go in<>: T: type for a type,N: uint / B: bool for values, with defaults. A
where clause states constraints checked at elaboration; the error points at the instantiation
that violated it.
• Ports are declared in the body within / out. inout does not exist; a top-level pad uses
tri<T> and is the only bidirectional signal.
• Port order is irrelevant: connections are always by name.
7.2 Instantiating
let rx_fifo = Fifo<u8, 64>(push: uart.rx) // clk, rst inherited from the parent’s
default domain
let tx_fifo = Fifo<u8, Depth: 64>(clk: clk_io, rst: rst_io, push: dma.out)
cpu.rx = rx_fifo.pop
let fifo_full = rx_fifo.count == 64
• Every in port must be given, exceptclock/reset ports that match the parent’s default
domain, which are inherited. An unconnected input is an error; an unused output is fine
(reported bytern check –unused).
• Generic arguments are positional or named; types and values share one list.
• The result of an instantiation is a value whose fields are the module’sout ports. It can be
destructured: let Fifo { pop, count } = Fifo<u8>(push: s) .
• Shorthand: Fifo<u8>(push) connects the parent’spush to the port of the same name.
• @ dom after the argument list sets the domain for every clock/reset port of the instance that
is not named explicitly.
7.3 Elaboration-time code
Any for, if or let whose condition or range is a compile-time value is unrolled at elaboration.
There is no separategenerate syntax.

8 Bundles, clock domains and CDC
A bundle is a struct whose fields have directions; declaring a portin or out fixes every field’s
direction at once. One keyword,flip, replaces SystemVerilog interfaces and modports.
8.1 Bundles
pub bundle Valid<T: type> {
valid: bool
data: T
}
pub bundle Stream<T: type> {
valid: bool
data: T
flip ready: bool // flows against the bundle’s direction
}
pub bundle Axi4Lite<AW: uint = 32, DW: uint = 32> {
aw: Stream<uint<AW>>
w: Stream< struct { data: uint<DW>, strb: bit<DW/8> }>
flip b: Stream<bit<2>>
ar: Stream<uint<AW>>
flip r: Stream<struct { data: uint<DW>, resp: bit<2> }>
}
• On anin port, non-flipped fields are inputs andflip fields are outputs; on anout port
the reverse. Nesting composes:flip b on anin Axi4Lite makes b.valid an output and
b.ready an input.
• A bundle value can be assigned whole (cpu.rx = fifo.pop), field by field (tx.ready =
...), or built with a literal (Stream { valid: true, data: x } — only the non-flipped
fields appear in a literal). Assigning whole connects both directions in one line.
• fn items inside abundle body getself. The standardStream has fire() -> bool (valid
and ready), map(f) and skid().
8.2 Clock domains
A domain is aclock plus, optionally, areset; the two travel together.
module Top {
in sys_clk: clock
in sys_rst: reset<async, low>
in pix_clk: clock
domain sys = (sys_clk, sys_rst) // named domains when a module has several
clocks
domain pix = (pix_clk) // no reset
let dma = Dma(bus: cpu.bus) @ sys
let video = Scanout(fb: dma.fb) @ pix
}

• A module with oneclock port has an implicit, unnamed default domain. A module with

9 Compile-time evaluation
Everything that SystemVerilog does with parameters,localparam, $clog2, generate and the
preprocessor, Tern does with one small, deterministic compile-time language:const values, const
fn, and ordinaryif/for over them.
9.1 Compile-time values
• const Name: T = expr at package or module level.T is usually widthlessuint/sint/bool,
but any type works.
• Generic parameters are consts inside the module.
• Widthless uint/sint are arbitrary precision at compile time; there is no 32-bit overflow in
parameter arithmetic.
• A value is compile-time if every input is: a literal, a const, a generic, a loop index of a const
range, or a call of aconst fn on those.
9.2 const fn
const fn clog2(n: uint) → uint {
var r = 0
while (1 << r) < n { r = r + 1 }
r
}
const fn crc_table(poly: uint<32>) → [uint<32>; 256] {
var t: [uint<32>; 256]
for i in 0..256 {
var c = i as uint<32>
for _ in 0..8 { c = if c[0] { (c >> 1) ^ poly } else { c >> 1 } }
t[i] = c
}
t
}
const Crc32Table: [uint<32>; 256] = crc_table(0xEDB88320) // computed once, becomes
a ROM
• const fn has var, while, for, if, match, recursion, arrays and structs. It cannot read
signals, instantiate modules or do I/O. Evaluation is bounded (–const-eval-limit, default
107 steps), so a runaway loop is a compile error, not a hang.
• A const fn called with signal arguments is just afn: the same source gives a ROM at
compile time or a combinational circuit at run time.while is rejected in that case, since it
is unbounded.
9.3 Static checks
• static_assert(cond, "message") anywhere a const is in scope; fires at elaboration with
the instantiation path.

=====PAGE=====

• where clauses on generics are sugar forstatic_asserts evaluated at the instantiation site.
• const_log("...{}...", value) prints during elaboration.
9.4 Type-level computation
type aliases may depend on consts:type Addr = uint<clog2(Depth)>. typeof(expr) names
the type of an expression,T::WIDTH the width of any type,T::MAX/T::MIN its extreme values.
Bundles can be generic over other bundles. There is deliberately no type-levelif; a module that
needs two shapes is two modules or anenum payload.
9.5 No preprocessor
‘ifdef becomes a bool generic or a feature flag in tern.toml [features], read as
cfg::feature_name. ‘define macros becomeconst or const fn. ‘include becomes use. The
compiler emits SystemVerilog with all of this resolved, so downstream tools never see a macro.

11 Verification
Tests, assertions and properties are part of the language and run withtern test on a built-in
cycle-based simulator. They use the same types and expressions as the design; nothing inside a
test or property is ever synthesized.
11.1 Unit tests
test "fifo preserves order" {
let dut = sim Fifo<u8, 4>() // harness owns clk/rst of the default
domain
dut.reset() // asserts reset for 2 cycles, then releases
for v in [1, 2, 3, 4] {
dut.push = Stream { valid: true, data: v }
dut.step() // one clock edge; combinational logic
settles after it
}
dut.push.valid = false
expect dut.count == 4
dut.pop.ready = true
for v in [1, 2, 3, 4] {
expect dut.pop.valid and dut.pop.data == v
dut.step()
}
expect !dut.pop.valid
}
• sim Module<...>(inputs...)builds a simulation handle. Inputs not given at construction
are driven later by assignment; areg’s current value and any internal signal are readable by
path (dut.rx_fifo.count). Internal signals cannot be written; a signal a test must drive is
exposed with#[test_port].
• step(n = 1) advances n cycles of the default domain;step_until(cond, max = 1000)
runs untilcond holds and fails atmax; settle() evaluates combinational logic without a
clock. With several domains:dut.sys.step(), dut.pix.step(), ordut.run(ns: 500)
using the periods from#[clock(hz)].
• expect condrecords a failure and continues;assert condstops the test. Both print the
expression with the values of its operands and the cycle number.
• log("...{}...", x) prints; dut.dump("waves.vcd") records a VCD waveform (readable
by GTKWave and Surfer).
• tern test runs every test in parallel, with a filter, a seed,–waves (dump on failure) and
–cover.

12 Standard library
std ships with the compiler and is written entirely in Tern. Every module in it is generic, carries
tests and properties, documents its latency as aconst, and speaks the sameStream handshake,
so a design is assembled from parts that fit without adapters. The reference is generated from the
sources and published at tern-lang.com/std;tern doc std::<pkg> shows it offline.
12.1 Rules every component follows
1. Generic over the payload type (T: type) and sized byuint generics withwhere constraints;
no magic widths.
2. One handshake: Stream<T> (valid/ready/data) between components,Valid<T> (no back-
pressure) where it is enough. Width and rate changes are explicit components, never hidden
in a port.
3. Latencyandthroughputarepublishedconstants( Fifo::LATENCY,Multiplier<..>::LATENCY);
the documentation tables are generated from them.
4. Every component has atest per documented behaviour and at least oneproperty for its
invariant;tern test std runs them all.
5. Reset values, encodings and target inference are attributes with sensible defaults, overridable
at the instance.
6. Nothing in std is vendor-specific except std::target::*, which wraps primitives the
language cannot express.
7. Every component follows the naming scheme: modulesUpperCamel, portssnake_case, an
input stream isin or push, an output streamout or pop, and the first generic is the payload
type.

13 Toolchain
One binary,tern, does everything from project creation to formal proof. Its only required output
is readable SystemVerilog, so Tern never needs vendor support to be usable.
13.1 Pipeline
Every command runs the same front half: parse, check (types, widths, drivers, latches, CDC,
unused) and elaborate (generics,const fn, unrolling) into a typed intermediate representation
(IR). The IR — modules, signals with domains, assignments, memories, assertions — is the only
thing the back ends see, so the SystemVerilog emitter, the simulator, formal and the language
server cannot disagree about a design. It is serialized as JSON with a documented schema and is
a stable contract from version 1.0.

13.3 Emitted SystemVerilog
• One .sv per Tern module, names preserved. Generics becomeparameters where SystemVer-
ilog allows and are monomorphized where it does not (T: type always monomorphizes:
Fifo_u8_64).
• Idiomatic output: always_ff/always_comb, logic, packed structs and enums,unique
case. No tool-specific constructs;–std verilog2005 emits plain Verilog.
• Line markers (// tern: fifo.tern:42 ) so synthesis and simulator messages map back;
tern remap translates tool logs to Tern locations.
• Attributes pass through unchanged; CDC primitives emit vendor attributes and a constraints
fragment.

An extern module is a typed black box: Tern checks the connections, trusts the inside, and passes
the file through to the build.tern import writes the declaration from the SystemVerilog port
list; the engineer adds the types (clock, reset<...>, bundles) that SystemVerilog cannot express.
Tests that include extern modules run through the Verilator backend (tern test –backend
verilator), which is also the fast path for large designs.
13.5 Migration path
1. tern new, thentern import the existing tree: every SystemVerilog module becomes an
extern. The build works on day one.
2. Rewrite leaf modules in Tern one at a time, with atest for each; the emitted SystemVerilog
replaces the original in the same flow.
3. Move interfaces to bundles as the modules on both sides are converted.
4. Delete extern declarations as they empty out.

13.7 Implementation in C
The reference compiler is written in portable C11 that also compiles as C99. It links only against
the C standard library and the operating system, and builds with one command:
cc -std=c11 -O2 -o tern src/unity.c # any C11 compiler
cc -std=c99 -O2 -o tern src/unity.c # the same tree as C99
make # incremental build (POSIX make)
build.bat # MSVC, cl /std:c11
Language rules
• Subset. C11 without compiler extensions, restricted to what also compiles with-std=c99:
no _Generic, no<threads.h>, no<stdatomic.h>, no variable-length arrays, no anonymous
structs or unions.TERN_STATIC_ASSERT expands to_Static_assert under C11 and to the
negative-array-size idiom under C99.
• Compilers. GCC, Clang and MSVC (2019 16.8 or newer,/std:c11) on Linux, macOS and
Windows. TCC builds the tree as a smoke test that nothing compiler-specific crept in.
• Zero third-party dependencies.Everything usually pulled from a library is in the tree:
arena allocator, string interning, hash maps, an arbitrary-precision integer for compile-time
arithmetic, a JSON reader and writer (IR and LSP), a TOML-subset reader, a VCD writer,
UTF-8 handling. Yosys, SymbiYosys, Verilator andgit are optional external programs,
called as subprocesses and found onPATH, never linked.

• One platform layer. os.h with os_posix.c and os_win32.c: files and directories,

14 Decisions
The following questions were open in the first draft and are settled; the rest of this specification is
written against them.
# Question Decision
1 X-propagation Tern stays 2-state. Reset gaps are found by the
uninitialized-register check and per-seed randomization. An
optional –xprop simulation mode may come later; 4-state
never enters the language.
2 Register assignment
operator
One =; the enclosing block gives it its meaning; the LSP shows
the kind on hover.
3 Signed/unsigned mixing Strict: an error until one side is cast.
std::math::widen_signed covers the common case.
4 Latches Never expressible in Tern; imported with extern module.
5 Implementation language C: portable C11 that also compiles as C99, no third-party
dependencies. The compiler, simulator, formatter and LSP are
one C project.
6 Driving internal signals
from tests
No force; a signal a test must drive is exposed with

7 Internal tri-state Forbidden; tri<T> exists only on#[top] ports.
8 Package registry Git-based: dependencies are git URLs pinned to tags or

9 Temporal property
language
The subset in the Verification chapter; repetition operators are

10 Clock enables and gating Enables are inferred fromif in on blocks; true gating is

A Grammar
The grammar in EBNF.NL is a newline or a semicolon. Expressions and statements are abbreviated
where they follow Rust/Go conventions; precedence is given in Table 3.2.
file = "package" path NL { use } { item } ;
use = "use" path [ "::" ( "*" | "{" ident { "," ident } "}" ) ] NL ;
item = [ "pub" ] ( module | extern_mod | bundle | struct | enum | const | fn
| type_alias | regmap ) | test | property | sequence ;
module = attrs "module" ident [ generics ] [ where ] "{" { mod_stmt } "}" ;
extern_mod = attrs "extern" "module" ident "(" string ")" [ generics ] "{" { port } "}" ;
generics = "<" generic { "," generic } ">" ;
generic = ident ":" ( "type" | type ) [ "=" expr ] ;
where = "where" expr { "," expr } ;
mod_stmt = port | domain | let | var | reg | mem | const | fn | enum | struct
| type_alias | comb_block | on_block | assign | elab_if | elab_for
| static_assert | property | sequence ;
port = ( "in" | "out" ) ident ":" type [ attrs ] NL ;
domain = "domain" ident "=" "(" ident [ "," ident ] ")" NL ;
let = "let" pattern [ ":" type ] "=" expr NL ;
var = "var" ident ":" type [ "=" expr ] NL ;
reg = "reg" ident ":" type [ "=" expr ] [ "@" ident ] NL ;
mem = attrs "mem" ident ":" "[" type ";" expr "]" [ "=" expr ] NL ;
const = "const" ident ":" type "=" expr NL ;
fn = [ "const" ] "fn" ident [ generics ] "(" [ params ] ")" " →" type block ;
type_alias = "type" ident [ generics ] "=" type NL ;
regmap = "regmap" ident "{" { reg_entry } "}" ;
reg_entry = int ident ":" access ( type | "{" fields_at "}" | type " →" type ) NL ;
access = "rw" | "ro" | "wo" | "w1c" | "rw1s" ;
comb_block = "comb" block ;
on_block = "on" ident block ;
assign = lvalue "=" expr NL ;
elab_if = "if" expr block [ "else" ( elab_if | block ) ] ;
elab_for = "for" pattern "in" expr block ;
static_assert = "static_assert" "(" expr [ "," string ] ")" NL ;
block = "{" { stmt } [ expr ] "}" ;
stmt = let | var | assign | if | match_stmt | for | while | assert | NL ;
if = "if" expr block [ "else" ( if | block ) ] ;
match_stmt = "match" expr "{" { pattern { "|" pattern } " ⇒" ( block | stmt ) "," } "}" ;
for = "for" pattern "in" expr block ; (* const range only *)
while = "while" expr block ; (* const fn only *)
assert = ( "assert" | "expect" ) expr [ "," string ] NL ;
expr = if_expr | match_expr | binary ;
if_expr = "if" expr block "else" ( if_expr | block ) ;
match_expr = "match" expr "{" { pattern { "|" pattern } " ⇒" expr "," } "}" ;
binary = unary { binop unary } ;
unary = [ "-" | "!" | "~" | "&" | "|" | "^" ] postfix ;
postfix = primary { "." ident | "[" expr [ ":" expr ] "]" | "(" [ args ] ")" | "as" type }
;
primary = literal | path | "(" expr { "," expr } ")" | "[" [ expr { "," expr } ] "]"
| struct_lit | instance | "sim" instance | block ;
instance = path [ generic_args ] "(" [ named_args ] ")" [ "@" ident ] ;
struct_lit = path "{" [ ident [ ":" expr ] { "," ident [ ":" expr ] } [ "," ".." ] ] "}" ;
